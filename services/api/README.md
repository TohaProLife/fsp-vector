# API ФСП Вектор

Самостоятельная реализация серверной части. Конкурентный код не используется. Runtime проекта запускается корневыми скриптами; API также запускается отдельно из `services/api`:

```powershell
..\..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Для PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://...`; секреты хранятся в локальной конфигурации, не в Git. По умолчанию отдельный запуск использует документированный SQLite fallback. Применение миграций:

```powershell
..\..\.venv\Scripts\python.exe -m alembic upgrade head
```

В полном локальном профиле `AUTO_CREATE_SCHEMA=false`: схему создаёт Alembic. Автоматический `create_all` разрешён лишь явно настроенному локальному/тестовому профилю. Начальная миграция зафиксирована явными DDL-операциями и включает таблицы OIDC и judge. Для будущих изменений создавайте новую ревизию.

## Реализованные контуры

- Регистрация, солёный медленный парольный hash, непрозрачные серверные сессии, HttpOnly cookie, CSRF + Origin, ограничение неудачных входов.
- Подтверждение email одноразовой ссылкой, явная демонстрационная почта, настоящая SMTP-доставка через durable outbox с повторными попытками.
- Ручной профиль, PDF-импорт в проверяемый черновик, Unicode PDF-экспорт, обязательный опрос, паспорт и история.
- Сохранённые попытки, серверное время, закрытые oracle, объективная проверка движком, подтверждение категории, cooldown и история показов семейств.
- Раздельные согласия, публикация, отзыв обработки и доступа к контактам, принадлежность ID демонстрационного реестра ФСП.
- Компания, потребности, извлечение черновика, категории, фильтры, объяснимый подбор, сохранённые и уточнённые подборки.
- Приглашения без обязательной вакансии, обязательная зарплата и компания, переписка, атомарное принятие, company-scoped grants, отзыв, блокировка и жалоба.
- Вакансии, самостоятельные отклики, статусы; практика с объективной проверкой либо явно субъективным отзывом компании.
- Уведомления, SSE с восстановлением, persistent outbox, подписанный ATS webhook и идемпотентный delivery ledger.
- Встроенные OpenAPI `/docs`, `/openapi.json`, Problem Details, request ID, запрет кэширования приватных ответов, верхняя граница тела запроса даже при chunked upload.

## Существенные инварианты

1. Результат задаёт сервер; `confirmed_grade` нельзя изменить PATCH профиля.
2. Демо-попытка и практика не присваивают категорию. Неуспех не отменяет ранее подтверждённый уровень.
3. Доступ к контактам ограничен одной компанией. Повтор старого accept/application не восстанавливает отозванное разрешение.
4. Сохранённые подборки повторно проверяют публикацию, email, согласие, блокировку и grants при каждом чтении.
5. Отзыв обработки и конкурентная публикация/отклик сериализуются блокировкой строки кандидата; разрешение не остаётся активным после отзыва.
6. Source `SELF_DECLARED`, `ASSESSMENT_VERIFIED`, `FSP_DEMO_CONFIRMED`, `PRACTICE_OBSERVED` и `COMPANY_REVIEWED` обозначают разные основания. Субъективный отзыв компании не добавляет глобальное подтверждение.
7. Экзамен сохраняет измеренную область; запрошенные Python/FastAPI не становятся автоматически проверенными навыками.
8. Пользовательский Python/JavaScript не запускается на этом Windows-хосте. Отдельный judge fail-closed; доступна ограниченная SQL/декларативная проверка только над отдельными синтетическими данными.
9. Worker использует `FOR UPDATE SKIP LOCKED`, savepoints и идемпотентный ledger. SMTP имеет семантику at-least-once: при аварии после приёма письма сервером возможен повтор со стабильным Message-ID.
10. ATS адрес задаёт оператор развёртывания; API работодателя не принимает произвольный URL. Подписывается `timestamp + '.' + raw_body`; приватные контакты не копируются в событие.

## Тесты и подтверждённые факты

```powershell
.venv\Scripts\python.exe -m pytest services/api/tests/test_domain_api.py -q
$env:RUN_PG_AUDIT='1'
.venv\Scripts\python.exe -m pytest services/api/tests/test_postgres_concurrency.py -q --tb=short
```

Команды выше запускаются из корня репозитория. PostgreSQL-аудит читает секреты `.local/runtime.json`, создаёт уникальную БД `vector_backend_audit_*` и удаляет именно её после тестов. Основная БД `vector` не очищается. Не используйте `--showlocals` при диагностике подключений с секретами.

На 7 октября 2026:

- **21 интеграционный тест API прошёл**: реальные операции, движок, независимый решатель по публичным данным, разграничение ролей, CSRF, email, private oracle, scoped contacts, отзыв, сохранённая выдача, ФСП ownership, DB salary constraints, PDF, SMTP/ATS retries и ручная практика.
- **7 тестов прошли на настоящем PostgreSQL 18.6**: параллельный start, submit, accept/withdraw, повтор accept, два outbox worker с SKIP LOCKED, отзыв обработки против публикации и отклика.
- Совместный прогон **28 passed, 1 dependency deprecation warning**, 62,83 секунды при одновременной работе других процессов. Это длительность тестового набора, не нагрузочная метрика API.
- Human-pilot и эмпирическая калибровка профессиональных грейдов остаются `NOT_MEASURED`. Отдельные синтетические проверки движков находятся в `evaluation/`.
- Настоящий Linux/runsc judge не доступен на текущем Windows-хосте; API сообщает эту границу.

Дополнительный аудит PDF-импорта: **9 тестов прошли**, совместно с API — **30 passed, 1 warning**, 11,67 с. Проверены настоящий Unicode PDF и точные offsets/quote, повреждённый/зашифрованный файл, превышение числа страниц, отсутствие текста, исчерпание слотов, timeout, чрезмерный ответ дочернего процесса и безопасный отказ при ошибке Windows JobObject. Схема БД не менялась.

PDF читает отдельный доверенный Python-процесс без shell и исполнения пользовательского исходного кода. Вход ≤3 МБ, ≤15 страниц, текст ≤40 000 Unicode codepoints, вывод ≤256 КБ; три слота и deadline обработки 6 с. Linux дополнительно ограничивает AS 512 МБ и CPU 4 с. На Windows собственный дочерний процесс помещается в анонимный JobObject: память 512 МБ, один активный процесс и kill-on-close; ошибка назначения закрывает импорт без неограниченного fallback. Чтобы лимит одного процесса работал, запускается настоящий Python interpreter с фиксированным каталогом зависимостей вместо Windows venv launcher. Секреты API не передаются в environment ребёнка. Это граница ресурсов доверенного парсера, не общий sandbox для пользовательского кода. Исходный PDF не сохраняется в постоянном хранилище. Точные span offsets относятся к собственному `source_text`; единица — `unicode_codepoint`.

## Настройки транспорта

`SMTP_HOST`, `SMTP_PORT`, `SMTP_SENDER` включают доставку worker. Без SMTP в локальном профиле письмо доступно в явном demo inbox; отсутствие производственного транспорта не считается успешной отправкой.

`ATS_WEBHOOK_URL` и `ATS_WEBHOOK_SECRET` включают HTTP-доставку. HTTPS обязателен, кроме localhost/Compose receiver. Worker не следует redirect и сохраняет retry при ошибке. Без URL только в `LOCAL_DEMO=true` работает явно обозначенный локальный ledger.

`LOCAL_DEMO=true` включает синтетические аккаунты и mailbox, поэтому локальный API привязан к loopback. Производственная конфигурация должна отключить этот режим, использовать HTTPS, надлежащую доставку почты, резервное копирование и организационную процедуру обработки персональных данных.
